# PGC Controlled Training Plan

## Governing principle

PGC will be built through progressive capability integration. No full pretraining run begins before the router, evidence boundaries, protected tests and recovery controls are operational.

## Phase 0: architecture validation

- validate imports and configuration objects
- test cognitive routing and abstention
- consolidate memory policy conflicts
- connect PHCS, PIMF, RaR and PCECE adapters
- verify evidence-class separation

## Phase 1: synthetic cognition

- alternating-state tracking
- parity
- modular arithmetic
- delayed induction
- multi-register updates
- controlled memory retention and forgetting

This phase uses generated data with fixed scripts, seeds and protected length generalisation.

## Phase 2: small open benchmarks

- COCO/BBOB for optimisation
- selected OpenML and UCI tasks
- OASST1 for dialogue structure and response ranking
- Mini LibriSpeech or a small Common Voice locale
- small COCO or ImageNet-derived feature trials where terms permit

## Phase 3: cross-domain routing

PGC receives mixed tasks and must select the correct expert configuration without receiving the domain label directly.

Required baselines:

- static single expert
- oracle expert selection
- random router
- confidence-only router
- PGC evidence and coherence router

## Phase 4: adaptive memory

- Titans memory as context
- Titans memory as layer
- gated memory branch
- MIRAS YAAD
- MIRAS MONETA
- MIRAS MEMORA
- PGC coherence-gated memory

## Phase 5: sequence backbones

- matched Mamba-2 baseline
- Mamba-3 SISO candidate
- Mamba-3 MIMO candidate
- attention control model

## Phase 6: smooth handover and continual learning

- cosine baseline
- Warmup-Stable-Decay
- stable-phase resume
- decay-phase quality upgrade
- loss-spike rollback tests
- catastrophic-forgetting tests

## Phase 7: distributed execution

- TorchTitan smoke test
- distributed checkpoint round trip
- fault-tolerant restart
- NVIDIA or AMD scaling
- AWS Neuron Mamba-2 comparison when infrastructure is available

## Promotion gates

A capability can be activated in the main PGC configuration only when:

1. its source and licence record is complete
2. its implementation passes tests
3. its validation beats or complements the control under predefined criteria
4. its failure modes are documented
5. its memory, compute and latency costs are measured
6. its effect on coherence and uncertainty is acceptable
7. rollback is possible

## No automatic self-integration

Learning outputs may propose changes. They do not automatically alter the protected PGC configuration. Promotion requires recorded evidence and explicit approval.
