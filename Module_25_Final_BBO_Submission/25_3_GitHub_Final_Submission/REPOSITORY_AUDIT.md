# Component 25.3: Final GitHub Repository Audit

## Purpose

This audit is based on the grading information currently available for the final GitHub submission. It should be checked again against the live Component 25.3 page before submission.

## Known grading criteria

| Criterion | Required evidence | Current action |
| --- | --- | --- |
| Code is clear, well commented and easy to run, with reproducible results | Analysis scripts, figure scripts, dependencies, fixed seeds where relevant and concise run instructions | Final repository-wide reproducibility check required |
| Datasheet is complete and included | Final assessment-facing datasheet linked prominently from the root README | Create or confirm final capstone datasheet |
| Model card is complete and included | Final assessment-facing model card linked prominently from the root README | Create or confirm final capstone model card |
| README contains an approximately 100-word non-technical explanation of the project and results | Plain-language project summary near the top of the root README | Add final summary and check approximate length |
| Repository is well organised and contains all relevant project files | Clear assessment navigation, complete Weeks 01 to 13, valid links, no placeholders, extensions separated from assessed evidence | Perform final navigation and file audit |

## Final audit sequence

1. Confirm Weeks 01 to 13 are complete and correctly numbered.
2. Confirm Week 13 inputs and outputs match the verified final round.
3. Confirm final best coordinate and value for F1 to F8.
4. Confirm analysis scripts run from documented dependencies.
5. Confirm generated results can be reproduced from committed source data.
6. Confirm datasheet and model card are complete and directly linked.
7. Confirm the root README contains the required non-technical summary.
8. Confirm all assessment navigation links work.
9. Confirm figures and reflection links point to existing files.
10. Remove unfinished placeholders, obsolete instructions and accidental conversational text.
11. Keep Advanced Extension Series and SOC visibly separated from the assessed thirteen-round history.
12. Confirm the public repository remains readable to assessors while the main branch protections remain appropriate.

## Submission principle

The assessor should not need to search the repository to establish that a criterion has been met. Each required item should be directly visible from the root README and traceable to the underlying evidence.
